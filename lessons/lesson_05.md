# Урок 05. WHERE и AND

---

## Производственный контекст

Руслан, на прошлом уроке ты научился выбирать колонки из таблицы. Но на производстве экономисту почти никогда не нужна вся таблица целиком.

Вот реальные вопросы, которые возникают каждый день:

- «Покажи только активные материалы» — чтобы не видеть архивные и заменённые.
- «Покажи материалы категории fabric (ткань)» — чтобы проверить цены на обивочные материалы.
- «Покажи модели кресел со статусом test» — чтобы убедиться, что тестовые модели не попали в производственный план случайно.
- «Покажи строки плана, которые уже утверждены» — чтобы видеть только то, что реально пойдёт в производство.

На все эти вопросы отвечает **WHERE** — команда фильтрации строк.

Без WHERE ты получаешь всю таблицу и ищешь нужные строки глазами. С WHERE — PostgreSQL делает это за тебя.

---

## Теория

### Словами

Представь, что у тебя на столе лежит стопка документов по всем материалам — 50 листов. Тебе нужно найти только те, где категория «ткань». Что ты делаешь? Перебираешь листы, смотришь на категорию, откладываешь подходящие.

WHERE делает то же самое, но за микросекунды.

**WHERE** — это условие отбора строк. PostgreSQL просматривает каждую строку таблицы и решает: подходит — покажи, не подходит — пропусти.

### Схема

```text
SELECT
    column_1,
    column_2
FROM table_name
WHERE condition;
```

Где `condition` — это условие, которое PostgreSQL проверяет для каждой строки.

### Как выглядят условия

Самое простое условие — сравнение колонки со значением:

```text
WHERE category = 'fabric'
```

Читается: «где категория равна fabric».

Важно: **текстовые значения обязательно в кавычках**. `fabric` без кавычек PostgreSQL воспримет как имя колонки, а не как текст.

### Типы условий в WHERE

| Оператор | Что проверяет | Пример для производства |
|---|---|---|
| `=` | Равно | `status = 'active'` |
| `<>` или `!=` | Не равно | `status <> 'archived'` |
| `>` | Больше | `current_price > 2000` |
| `<` | Меньше | `standard_labor_minutes < 60` |
| `>=` | Больше или равно | `planned_quantity >= 20` |
| `<=` | Меньше или равно | `current_price <= 5000` |

### Как соединить несколько условий через AND

Если нужно выполнить два условия одновременно, используется **AND**:

```sql
WHERE category = 'fabric'
  AND status = 'active';
```

Читается: «где категория равна fabric И статус равен active».

AND означает, что оба условия должны быть истинны одновременно. Если хотя бы одно не выполняется, строка не попадает в результат.

### Как понять, сколько строк вернёт WHERE

PostgreSQL сам решает, сколько строк подходят под условие. Ты не можешь знать заранее точное количество, но можешь примерно оценить:

- `WHERE status = 'test'` — вернёт, скорее всего, 1-2 строки (тестовых моделей мало).
- `WHERE status = 'active'` — вернёт больше половины таблицы (большинство моделей активны).
- `WHERE current_price > 100000` — возможно, не вернёт ни одной строки (таких дорогих материалов нет).

## Тестовый запрос

Проверь, что колонка `status` в таблице `chair_models` содержит ожидаемые значения. Просто посмотри, какие статусы бывают:

```sql
SELECT DISTINCT status
FROM chair_models;
```

Этот запрос (DISTINCT мы пока не проходили, просто выполни его для проверки) покажет все уникальные значения колонки status: active, archived, test.

Зачем нужен тестовый запрос: если ты не знаешь, какие значения есть в колонке, ты можешь написать `WHERE status = 'aktiv'` и не получить ни одной строки, думая, что запрос неправильный. Тестовый запрос показывает, какие значения реально существуют.

## Пример SQL

Найдём активные материалы категории fabric (ткань):

```sql
SELECT
    material_code,
    material_name,
    category,
    unit,
    current_price,
    status
FROM materials
WHERE category = 'fabric'
  AND status = 'active';
```

Разберём построчно:

- `SELECT` — команда «покажи».
- `material_code, material_name, category, unit, current_price, status` — колонки, которые нужны экономисту. Только те, что важны для проверки тканей.
- `FROM materials` — берём данные из таблицы materials.
- `WHERE category = 'fabric'` — первое условие: оставляем только строки, где категория — fabric (ткань).
- `AND status = 'active'` — второе условие: дополнительно оставляем только активные материалы.
- `;` — конец запроса.

Важный нюанс: оба условия должны выполняться одновременно. Если материал — ткань, но архивный, он не попадёт в результат. Если материал активный, но не ткань — тоже не попадёт.

---

## Разбор результата

Запрос вернёт только те строки из materials, где одновременно `category = 'fabric'` и `status = 'active'`.

Пример результата:

```text
 material_code   | material_name | category | unit | current_price | status
-----------------+---------------+----------+------+---------------+--------
 FAB-PREMIUM-01  | Ткань Премиум | fabric   | м2   | 1250.50      | active
 FAB-STANDARD-01 | Ткань Стандарт| fabric   | м2   | 780.00       | active
```

Для экономиста это означает: «вот ткани, которые можно использовать для расчёта себестоимости». Архивные ткани (которые уже не закупаются) и заменённые (которые выводятся из ассортимента) отфильтрованы.

Если в результате 0 строк, возможные причины:

- в таблице нет материалов с категорией fabric;
- все ткани имеют статус, отличный от active;
- ты ошибся в написании — возможно, fabric написано как `fabric` (всё верно) или `Fabrics` (неверно, PostgreSQL различает регистр, если не указано иначе).

## Типичные ошибки Руслана

1. **Руслан забывает кавычки вокруг текста.**
   Почему это ошибка: `WHERE category = fabric` — PostgreSQL ищет колонку с именем fabric, а не текст «fabric». Ошибка «column "fabric" does not exist». Все текстовые значения — в одинарных кавычках.

2. **Руслан использует запятую вместо AND.**
   Почему это ошибка: WHERE не принимает запятые между условиями. `WHERE category = 'fabric', status = 'active'` — это синтаксическая ошибка. Условия соединяются через AND.

3. **Руслан путает = и <> (не равно).**
   Почему это ошибка: `=` находит совпадение; `<>` исключает значение. Если написать `WHERE status <> 'active'`, ты получишь все строки, которые не active — включая test и archived. Для отчёта это может оказаться не тем, что нужно.

4. **Руслан не указывает WHERE и получает всю таблицу.**
   Почему это ошибка: если забыть WHERE, PostgreSQL честно вернёт все строки. Для таблицы из 50 материалов это ещё нормально, но для таблицы с движениями склада (тысячи строк) — нечитаемый результат.

5. **Руслан пишет условие не по той колонке.**
   Почему это ошибка: если нужно найти ткани, а написать `WHERE material_name LIKE '%ткань%'` (мы ещё не проходили LIKE, это позже), можно пропустить материалы, где в названии нет слова «ткань», но категория fabric. Всегда проверяй, по какой колонке фильтруешь.

## Практическое задание

### Условие

Найди все активные материалы категории fabric (ткань) из таблицы materials.

Покажи колонки:

- `material_code`;
- `material_name`;
- `category`;
- `current_price`;
- `status`.

### Ожидаемый результат

Только материалы, где одновременно `category = 'fabric'` и `status = 'active'`.

Для экономиста это важно: видеть только актуальные ткани для расчёта себестоимости.

```text
 material_code   | material_name    | category | current_price | status
-----------------+------------------+----------+---------------+--------
 FAB-PREMIUM-01  | Ткань Премиум   | fabric   | 1250.50       | active
 FAB-STANDARD-01 | Ткань Стандарт  | fabric   | 780.00        | active
```

### Подсказка

Используй таблицу `materials`.

Соедини два условия через AND:

```sql
WHERE category = 'fabric'
  AND status = 'active'
```

Не забудь кавычки вокруг текстовых значений.

### Критерии проверки

- Использована только таблица `materials`.
- Есть SELECT, FROM и WHERE.
- В WHERE два условия, соединённые через AND.
- Первое условие: `category = 'fabric'`.
- Второе условие: `status = 'active'`.
- В SELECT выбранные колонки из условия.
- Результат не содержит строк с не-fabric категориями или не-active статусом.

## Разбор решения

Правильный запрос:

```sql
SELECT
    material_code,
    material_name,
    category,
    current_price,
    status
FROM materials
WHERE category = 'fabric'
  AND status = 'active';
```

Разберём каждую строку:

- `SELECT` — команда «покажи». PostgreSQL начинает формировать результат.
- `material_code,` — код материала (первая колонка). Для экономиста это краткий идентификатор ткани.
- `material_name,` — название материала (вторая колонка). Человекочитаемое имя.
- `category,` — категория (третья колонка). Здесь все строки будут со значением 'fabric' — результат фильтрации, но колонка включена, чтобы убедиться, что фильтр сработал.
- `current_price,` — текущая цена (четвёртая колонка). Цена за единицу измерения.
- `status` — статус (пятая колонка). Здесь все строки будут со значением 'active'. Запятой нет — последняя колонка.
- `FROM materials` — источник данных.
- `WHERE category = 'fabric'` — первое условие: оставляем только строки, где категория — fabric (ткань).
- `AND status = 'active'` — второе условие: дополнительно оставляем только активные материалы.
- `;` — конец запроса.

Почему колонка `category` включена в SELECT, если мы и так фильтруем по ней: это полезно для визуального подтверждения. Ты сразу видишь, что все строки имеют категорию fabric, и можешь убедиться, что WHERE сработал правильно.

Почему кавычки: 'fabric' и 'active' — это текст. В PostgreSQL текстовые значения всегда в одинарных кавычках. Если бы мы написали `WHERE category = fabric` (без кавычек), PostgreSQL подумал бы, что fabric — это имя колонки, и выдал бы ошибку.

## Почему это пригодится на работе экономиста

Без WHERE любой SQL-запрос возвращает **все** строки таблицы. На производстве это практически никогда не нужно.

Вот реальные сценарии, где WHERE нужен экономисту каждый день:

- **Актуальные цены:** `WHERE status = 'active'` — исключаем архивные и заменённые материалы, чтобы не учитывать их в себестоимости.
- **Утверждённый план:** `WHERE status = 'approved'` — смотрим только те строки плана, которые реально пойдут в производство, игнорируем черновики и отменённые.
- **Проверка остатков:** `WHERE available_quantity < min_stock_quantity` — находим материалы, которые нужно срочно заказать.
- **Контроль брака:** `WHERE defect_quantity > 0` — находим выпуски, где был брак, чтобы проанализировать причины.

Экономист, владеющий WHERE, может за 10 секунд найти нужные строки в любой таблице. Без WHERE он вынужден смотреть всю таблицу и искать глазами.
