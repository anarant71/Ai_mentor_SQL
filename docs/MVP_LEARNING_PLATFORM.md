# MVP Learning Platform: AI-Mentor Architecture

> **Версия:** 1.0
> **Дата:** 2026-05-25
> **Статус:** Архитектурный документ

---

## 1. Обзор платформы

AI-Mentor — это образовательная платформа с персональным AI-наставником для обучения SQL на примере производства офисных кресел. Платформа объединяет три ключевых компонента:

- **Контент** — уроки, задания, roadmap. Ученик проходит уроки, выполняет SQL-запросы в песочнице, получает проверку и обратную связь.
- **AI-наставник** — адаптивный слой, который отслеживает прогресс, выявляет слабые места, планирует повторение, даёт персональные рекомендации.
- **Автоматизация** — n8n-сценарии для напоминаний, отчётов, регулярных проверок и внешних интеграций.

Платформа рассчитана на одного ученика (Руслан, экономист мебельного производства) с нулевым опытом SQL. Все 50 уроков курса используют единую учебную БД производства офисных кресел.

## 2. Экран урока

### 2.1. Структура экрана

Экран урока — основная рабочая область ученика. Он состоит из следующих зон:

**Зона 1: Навигация**
- Заголовок: номер урока, название, модуль.
- Кнопки: «Предыдущий урок», «Следующий урок», «Roadmap».
- Индикатор прогресса: сколько уроков в модуле пройдено.

**Зона 2: Содержание урока**
- Markdown-контент урока (теория, примеры, SQL-блоки).
- Все 12 обязательных разделов урока отображаются последовательно.
- SQL-блоки подсвечены синтаксически и имеют кнопку «Открыть в SQL Sandbox».

**Зона 3: Панель действий**
- Кнопка «Выполнить задание» — открывает SQL Sandbox с предзаполненным контекстом задания.
- Кнопка «Спросить AI-наставника» — открывает чат с контекстом текущего урока.
- Кнопка «Отметить как пройденный» — появляется после успешной проверки задания.

**Зона 4: Статус навыков**
- Боковая панель (или вкладка): какие навыки покрывает текущий урок, текущий уровень ученика по каждому навыку, рекомендация по повторению, если навык «затухает».

### 2.2. Поведение

- Урок открывается в read-only режиме. Ученик читает, скроллит, изучает.
- SQL-примеры можно копировать или отправлять в песочницу одним кликом.
- После прочтения ученик нажимает «Выполнить задание» — система фиксирует факт начала выполнения.
- После успешной проверки задания урок отмечается как пройденный, навыки обновляются.

### 2.3. Offline-поведение (будущая версия)

- Контент урока кэшируется локально.
- Результаты заданий сохраняются в локальном хранилище и синхронизируются при подключении.

## 3. SQL Sandbox

### 3.1. Назначение

SQL Sandbox — это безопасная read-only среда, в которой ученик выполняет SQL-запросы к учебной БД. Песочница изолирована от реальных данных, не позволяет изменять таблицы и имеет ограничения по времени и объёму результата.

### 3.2. Архитектура

Песочница реализуется как отдельная PostgreSQL-схема (или отдельная БД), в которую развёрнута копия учебных таблиц с seed-данными.

**Уровни изоляции:**

| Уровень | Описание | Когда используется |
|---|---|---|
| **Полная изоляция** | Отдельная БД `training_sandbox` с read-only пользователем | Все учебные запросы ученика |
| **Частичная** | Основная БД, схема `sandbox`, read-only права | Будущая версия для продвинутых учеников |

### 3.3. Ограничения безопасности

- Пользователь песочницы имеет только `SELECT`-права на таблицы учебной схемы.
- Запрещены: `INSERT`, `UPDATE`, `DELETE`, `DROP`, `CREATE`, `ALTER`, `TRUNCATE`.
- Ограничение времени выполнения запроса: `statement_timeout = 30s`.
- Максимальное количество строк в результате: `1000`.
- Запрещены multi-statement запросы (только один SQL-запрос за раз).
- Все запросы логируются с меткой времени и ID задания.

### 3.4. Пользовательский интерфейс

**Поле ввода SQL:**
- Редактор кода с подсветкой синтаксиса PostgreSQL.
- Поддержка многострочного ввода.
- Автонумерация строк.
- Кнопка «Выполнить» (Ctrl+Enter).
- Кнопка «Очистить».

**Панель результата:**
- Таблица с результатом запроса (колонки + строки).
- Счётчик строк: «Показано 12 из 47 строк».
- Индикатор времени выполнения: «0.034 сек».
- Сообщение об ошибке (если запрос не выполнился) — понятным языком, не техническим.

**Контекст задания:**
- Если песочница открыта из урока, сверху отображается условие задания.
- Поле ввода может быть предзаполнено SQL-подсказкой из урока.
- Кнопка «Отправить на проверку» — отправляет запрос в систему проверки.

### 3.5. Future: Версия 2.0

- История выполненных запросов с возможностью вернуться к любому.
- Сравнение результатов двух запросов.
- Экспорт результата в CSV.
- Визуализация данных (простая диаграмма по результату).

## 4. Автоматическая проверка SQL

### 4.1. Стратегия проверки

Проверка SQL-заданий проходит в три этапа:

**Этап 1: Синтаксическая проверка (на стороне песочницы)**
- Запрос выполняется в песочнице.
- Если синтаксическая ошибка — ученик видит сообщение и может исправить сразу.
- Фиксируется первая попытка (даже с ошибкой).

**Этап 2: Проверка результата (серверная)**
- После успешного выполнения запрос отправляется на сервер.
- Сервер сравнивает результат ученика с эталонным результатом.

Методы сравнения:

| Метод | Что проверяет | Точность | Когда использовать |
|---|---|---|---|
| **Точное совпадение** | Колонки, типы, порядок, строки полностью совпадают | 100% | Простые задания (SELECT с конкретными колонками) |
| **Совпадение набора строк** | Строки совпадают (порядок не важен) | Высокая | Задания без ORDER BY |
| **Агрегатная проверка** | Совпадают агрегатные значения | 100% | GROUP BY задания |
| **AI-проверка** | AI оценивает логику запроса | ~95% | Сложные задания, CTE, оконные функции |

**Этап 3: AI Mentor feedback**
- После прохождения автоматической проверки AI Mentor формирует развёрнутую обратную связь:
  - что сделано правильно;
  - что можно улучшить;
  - какие типичные ошибки были избегнуты;
  - насколько запрос оптимален (будущая версия).

### 4.2. Алгоритм точного сравнения

```
1. Выполнить эталонный запрос → получить эталонный результат.
2. Выполнить запрос ученика → получить результат ученика.
3. Сравнить:
   a. Количество колонок.
   b. Имена колонок (регистронезависимо).
   c. Типы данных колонок.
   d. Количество строк.
   e. Значения в каждой ячейке.
4. Если все совпадает → проверка пройдена.
5. Если не совпадает:
   a. Определить, какой именно аспект не совпал (колонки, строки, значения).
   b. Отправить AI Mentor контекст для формирования feedback.
```

### 4.3. Обработка ошибок

| Ситуация | Действие системы |
|---|---|
| Запрос не выполнился (синтаксическая ошибка) | Показать ошибку в песочнице, попросить исправить |
| Запрос выполнился, но вернул не те колонки | AI Mentor объясняет, какие колонки ожидались |
| Запрос выполнился, колонки верные, но данные не совпадают | AI Mentor указывает на конкретные расхождения |
| Запрос выполнился, но слишком медленный (>5 сек) | AI Mentor предлагает оптимизацию (будущая версия) |

### 4.4. Эталонные запросы

Для каждого задания в БД хранится эталонный SQL-запрос. Эталонные запросы:
- написаны автором курса;
- проверены на учебной БД;
- хранятся в таблице `task_expected_answers` (см. раздел 9);
- не видны ученику (даже через API);
- используются только для сравнения и AI-анализа.

## 5. Хранение попыток

### 5.1. Что хранится

Каждая попытка выполнения задания фиксируется полностью:

| Поле | Тип | Описание |
|---|---|---|
| ID попытки | UUID | Уникальный идентификатор |
| ID ученика | UUID | Ссылка на users |
| ID задания | UUID | Ссылка на tasks |
| Номер попытки | Integer | Порядковый номер (1, 2, 3...) |
| SQL-запрос | Text | Полный текст запроса ученика |
| Статус выполнения | Enum | submitted, syntax_error, executed, reviewed, accepted, rejected |
| Результат (если выполнен) | JSONb | Колонки, строки, время выполнения |
| Ошибка (если не выполнен) | Text | Текст ошибки от PostgreSQL |
| Оценка | Numeric | 0.0 – 1.0 |
| Feedback AI | Text | Текст обратной связи от AI Mentor |
| Время начала | Timestamptz | Когда ученик открыл задание |
| Время отправки | Timestamptz | Когда ученик отправил запрос |
| Время проверки | Timestamptz | Когда получен результат |

### 5.2. Бизнес-логика

- Каждое задание можно отправлять **неограниченное количество раз**.
- Система хранит **все** попытки, не только последнюю.
- Первая успешная попытка закрывает задание (отмечается как выполненное).
- Последующие попытки (если ученик хочет улучшить или переделать) тоже сохраняются.
- AI Mentor анализирует динамику попыток: если ученик исправляет одну и ту же ошибку 3+ раза — система предлагает вернуться к теории.

### 5.3. Аналитика попыток

Система рассчитывает для каждого задания:
- количество попыток до первой успешной;
- общее количество попыток;
- среднее время между попытками;
- типы ошибок (синтаксические, логические, неверные колонки);
- прогресс от первой к последней попытке (улучшается ли качество).

## 6. Хранение навыков

### 6.1. Модель навыков

Навыки — это измеримые компетенции, которые ученик развивает в ходе курса. Каждый урок и каждое задание привязаны к одному или нескольким навыкам.

**Каталог навыков (skills):**

| Код навыка | Название | Категория |
|---|---|---|
| select_basic | Базовый SELECT | SQL |
| where_filter | Фильтрация WHERE | SQL |
| order_sort | Сортировка ORDER BY | SQL |
| group_agg | Агрегация GROUP BY | SQL |
| join_basic | Соединение таблиц | SQL |
| join_multi | Множественные JOIN | SQL |
| subqueries | Подзапросы | SQL |
| cte | CTE | SQL |
| window_func | Оконные функции | SQL |
| data_quality | Качество данных | SQL |
| calculations | Вычисления в SELECT | SQL |
| date_filter | Работа с датами | SQL |
| null_handling | Работа с NULL | SQL |
| view_create | Создание VIEW | SQL |
| production_context | Производственная аналитика | Domain |

### 6.2. Уровни навыков

Каждый навык имеет уровень от 0 до 5:

| Уровень | Описание | Что ученик может делать |
|---|---|---|
| 0 — Не изучался | Навык ещё не затронут | Ничего |
| 1 — Знакомство | Ученик прочитал теорию, но не практиковался | Объяснить словами |
| 2 — Базовый | Выполнено 1-2 простых задания | Написать простой запрос по шаблону |
| 3 — Уверенный | Выполнено 3+ задания, в том числе без подсказок | Написать запрос самостоятельно |
| 4 — Продвинутый | Выполнены задания повышенной сложности | Комбинировать навык с другими |
| 5 — Автоматизм | Многократная успешная практика с интервалом | Использовать без раздумий |

### 6.3. Атрибуты навыка для каждого ученика (student_skills)

| Поле | Описание |
|---|---|
| Уровень | 0-5 |
| Уверенность | 0.0 – 1.0 (насколько уверенно ученик применяет навык) |
| Количество попыток | Всего попыток по заданиям этого навыка |
| Успешных попыток | Сколько попыток были успешными |
| Дата последней практики | Когда ученик последний раз выполнял задание по этому навыку |
| «Затухание» | Процент снижения уверенности, если давно не практиковался |
| Evidence | JSONb: ссылки на успешные попытки (ID заданий и попыток) |

### 6.4. Обновление навыков

Навыки обновляются после каждого успешного выполнения задания по алгоритму:

```
1. Определить навыки, которые покрывает задание (из таблицы task_skills).
2. Для каждого навыка:
   a. Увеличить attempts_count на 1.
   b. Если попытка успешна — увеличить successful_attempts_count на 1.
   c. Пересчитать уровень:
      - 0 попыток → level = 0
      - 1 попытка успешна → level = 1
      - 3+ попытки, 80%+ успешны → level = 3
      - 5+ попыток, 90%+ успешны, были сложные задания → level = 4
      - practised_at > 7 дней → level может снизиться
   d. Пересчитать уверенность:
      - confidence = successful_attempts_count / max(attempts_count, 1)
      - Если с последней практики прошло > N дней, уверенность снижается.
```

## 7. Карта сильных и слабых сторон ученика

### 7.1. Визуализация

Карта навыков — это визуальный профиль ученика, который показывает:

- **Сильные стороны** — навыки с уровнем 3+ и уверенностью > 0.7.
- **Слабые стороны** — навыки с уровнем 1-2 ИЛИ уверенностью < 0.5.
- **Затухающие** — навыки, которые давно не практиковались (уровень снижается).
- **Неизученные** — навыки, которые ещё не затронуты курсом.

Карта отображается в виде матрицы или радарной диаграммы.

### 7.2. Логика формирования

```
Для каждого навыка из skills:
  Если уровень >= 3 И confidence >= 0.7:
    → сильная сторона
  Если уровень <= 2 ИЛИ confidence < 0.5:
    → слабая сторона
  Если с last_practiced_at прошло > 7 дней И уровень >= 1:
    → затухающий (пометить для повторения)
  Если уровень = 0:
    → неизученный
```

### 7.3. Использование карты

- **Ученик** видит карту на дашборде и понимает, над чем работать.
- **AI Mentor** использует карту для рекомендаций:
  - если слабая сторона по `where_filter` → AI предлагает дополнительные задания.
  - если затухает `join_basic` → AI планирует повторение.
  - если сильная сторона по `group_agg` → AI может пропустить простые задания и дать сложные.
- **Система** использует карту для адаптивного построения roadmap.

## 8. Система повторения забытых тем

### 8.1. Принцип

Система повторения основана на принципе интервального повторения (spaced repetition). Если ученик не практиковал навык больше N дней, система предлагает повторить.

### 8.2. Алгоритм

```
Проверка запускается:
- ежедневно (по расписанию);
- после завершения каждого урока;
- вручную (ученик нажал «Повторить»).

Для каждого навыка ученика:
  1. days_since_practice = today - last_practiced_at
  2. decay_rate = days_since_practice / skill_decay_threshold

  Где skill_decay_threshold зависит от уровня:
    level 1 → threshold = 3 дня (новичок забывает быстро)
    level 2 → threshold = 7 дней
    level 3 → threshold = 14 дней
    level 4 → threshold = 30 дней
    level 5 → threshold = 60 дней

  3. Если decay_rate >= 1:
     → навык требует повторения
     → уменьшить confidence на 5% за каждый день просрочки
     → найти последнее успешное задание по этому навыку
     → предложить ученику выполнить его снова (или аналогичное)
```

### 8.3. Механика повторения

- В дашборде появляется блок «Требует повторения» со списком навыков.
- По каждому навыку можно нажать «Повторить» → открывается задание, аналогичное успешно выполненному ранее.
- После успешного повторения confidence восстанавливается, уровень не снижается.
- Если повторение неуспешно → AI Mentor рекомендует перепройти соответствующий урок.
- После 3+ неуспешных повторений навык помечается как «требует переобучения» — AI предлагает перепройти урок с начала.

## 9. AI Mentor после каждой проверки

### 9.1. Контекст для AI

После каждой проверки задания AI Mentor получает структурированный контекст:

```json
{
  "student": {
    "name": "Руслан",
    "current_level": "beginner",
    "skill_profile": { "select_basic": 3, "where_filter": 2, ... }
  },
  "task": {
    "id": "uuid",
    "title": "Найди активные модели кресел",
    "skill_codes": ["where_filter", "select_basic"],
    "difficulty": 2
  },
  "submission": {
    "attempt_number": 2,
    "student_sql": "SELECT ...",
    "execution_result": { "columns": [...], "rows": [...] },
    "is_syntax_ok": true,
    "comparison_result": { "match": false, "differences": [...] }
  },
  "lesson_context": {
    "lesson_number": 5,
    "lesson_title": "WHERE и AND",
    "theory_summary": "Фильтрация строк через WHERE..."
  }
}
```

### 9.2. Что AI формирует в ответ

AI Mentor генерирует feedback в следующей структуре:

**1. Оценка попытки (1-2 предложения):**
- «Отлично, Руслан! Запрос выполнен верно.»
- «Хорошая попытка, но есть небольшая ошибка в условии WHERE.»

**2. Что сделано правильно (2-3 пункта):**
- «Ты правильно выбрал колонки из chair_models.»
- «Ты верно использовал WHERE для фильтрации.»
- «Кавычки вокруг 'active' стоят правильно.»

**3. Что нужно исправить (если есть ошибки):**
- «В условии WHERE ты написал status = active без кавычек. PostgreSQL воспринимает active как имя колонки, а не как текст. Нужно: status = 'active'.»
- «Ты забыл колонку category. Для отчёта экономисту важно видеть категорию кресла.»

**4. Подсказка (если нужно):**
- «Попробуй посмотреть в уроке раздел «Типичные ошибки Руслана», там разобрана похожая ситуация.»

**5. Связь с работой экономиста:**
- «Помни, что на производстве этот запрос помогает быстро исключить архивные материалы из расчёта себестоимости. Без WHERE ты бы увидел все 50 материалов и искал глазами активные.»

**6. Рекомендация (опционально):**
- «Рекомендую повторить раздел «Теория» в уроке 5 — там подробно разобраны кавычки в WHERE.»

### 9.3. Тон AI Mentor

- Дружелюбный, поддерживающий.
- Обращение на «ты» по имени Руслан.
- Фокус на производственном контексте (кресла, материалы, себестоимость).
- Не ругает за ошибки — объясняет, почему возникла ошибка и как её исправить.
- Хвалит за правильные решения.

## 10. Схема БД платформы

Схема БД платформы расширяет существующую `mvp_schema.sql` и включает следующие таблицы.

#### Таблицы пользователей и профилей

**users**

- email (text, unique)
- password_hash (text)
- display_name (text)
- role (enum: student, admin, mentor)
- status (enum: active, inactive, blocked)
- last_login_at (timestamptz)
- created_at, updated_at (timestamptz)

**student_profiles**
- id (UUID, PK)
- user_id (UUID, FK -> users.id, unique)
- learning_goal (text)
- current_level (enum: beginner, junior, middle, strong_middle, advanced)

- timezone (text)
- weekly_study_minutes (int)

#### Таблицы контента

**skills**
- id (UUID, PK)
- code (text, unique)
- title (text)
- description (text)
- category (text)
- status (enum: active, archived)
- created_at, updated_at (timestamptz)

**lessons**
- id (UUID, PK)
- primary_skill_id (UUID, FK -> skills.id)
- slug (text, unique)
- title (text)
- summary (text)
- content_path (text) — путь к Markdown-файлу в lessons/
- difficulty (int, 1-5)
- estimated_minutes (int)
- status (enum: draft, published, archived)
- prerequisites (jsonb) — массив ID уроков, которые нужно пройти перед этим

**tasks**
- id (UUID, PK)
- lesson_id (UUID, FK -> lessons.id)

- description (text)
- task_type (enum: sql, text, quiz, project, review, diagnostic)

**task_skills**
- task_id (UUID, FK -> tasks.id)
- skill_id (UUID, FK -> skills.id)

**submissions**
- id (UUID, PK)
- student_id (UUID, FK -> users.id)
- task_id (UUID, FK -> tasks.id)
- attempt_number (int)
- sql_text (text) — полный SQL-запрос ученика
- execution_status (enum: submitted, syntax_error, executed, reviewed, accepted, rejected)
- execution_result (jsonb)
- error_text (text)
- score (numeric, 0.0-1.0)
- feedback (text) — текст feedback от AI Mentor
- started_at (timestamptz)
- submitted_at (timestamptz)
- reviewed_at (timestamptz)

**lesson_progress**
- id (UUID, PK)
- student_id (UUID, FK -> users.id)
- lesson_id (UUID, FK -> lessons.id)
- status (enum: not_started, in_progress, completed, skipped)
- started_at (timestamptz)

- UNIQUE (student_id, lesson_id)

- description (text)
- difficulty (int)
- status (enum: locked, available, in_progress, completed, skipped)
- expected_outcome (text)

- title (text)

- id (UUID, PK)

### 12.2. Dashboard (главная страница)

Блоки:

1. **Приветствие** — «Руслан, продолжай обучение!» + текущий уровень.
2. **Следующий шаг** — кнопка «Продолжить урок N» (следующий не пройденный урок).
3. **Прогресс курса** — прогресс-бар: «12 из 50 уроков пройдено».
4. **Карта навыков (компактная)** — 5-6 ключевых навыков с индикаторами уровня.
5. **Требует повторения** — список навыков, которые пора повторить.
6. **Последняя активность** — что делал в прошлый раз, результат.
7. **AI Mentor** — короткая рекомендация: «Руслан, рекомендую повторить JOIN — прошло 10 дней с последней практики.»

### 12.3. Roadmap

- Вертикальная дорожка с шагами.
- Каждый шаг: номер, название, статус (пройден/активен/заблокирован).
- Активный шаг подсвечен.
- Пройденные — с галочкой.
- Заблокированные — серые с замком.

### 12.4. Карта навыков

- Матрица: навыки по строкам, уровни по столбцам.
- Цветовая индикация:
  - зелёный — уровень 4-5 (сильная сторона);
  - жёлтый — уровень 2-3 (средний);
  - красный — уровень 0-1 (слабая сторона);
  - серый — затухающий;
  - оранжевый — требует повторения.
- При клике на навык — детали: какие задания выполнены, последняя практика.

### 12.5. Чат с AI-наставником

- Чат-интерфейс (как Telegram/WhatsApp).
- Сообщения ученика (справа, синие) и AI (слева, серые).
- Контекстная панель: показывает текущий урок/задание (если чат открыт из контекста).
- Кнопка «Новый диалог» для общего вопроса (без контекста).
- История диалогов сохраняется и доступна.

## 13. MVP версия и будущие версии

### 13.1. MVP (Версия 1.0)

**Цель:** ученик может пройти урок, выполнить задание в песочнице, получить проверку и AI-feedback.

**Что входит:**
- [x] 50 уроков в Markdown (созданы по COURSE_GENERATION_PLAN.md).
- [x] Учебная PostgreSQL БД с 9 таблицами и seed-данными.
- [x] SQL Sandbox (read-only, изолированная схема).
- [x] Автоматическая проверка SQL (точное сравнение + sql_result).
- [x] Хранение попыток (submissions).
- [x] Базовая схема навыков (skills, student_skills).
- [x] AI Mentor feedback после каждой проверки (интеграция с LLM).
- [x] Backend API: auth, lessons, tasks, sandbox, submissions.
- [x] Frontend: dashboard, урок, sandbox, задание.
- [ ] n8n: базовый сценарий напоминания (если ученик не заходил 3 дня).

**Что НЕ входит в MVP:**
- Карта сильных и слабых сторон (будет версия 1.1).
- Система повторения забытых тем (будет версия 1.2).
- Адаптивный roadmap (будет версия 1.3).
- Полноценный чат с AI-наставником (будет версия 1.1).
- Визуализация данных (будет версия 2.0).

### 13.2. Версия 1.1 — Аналитика

- Карта сильных и слабых сторон на dashboard.
- Чат с AI-наставником (сохранение диалогов, контекст урока).
- Статистика попыток: среднее количество попыток, типы ошибок.
- Уведомления о прогрессе.

### 13.3. Версия 1.2 — Повторение

- Система интервального повторения (review_queue).
- Уведомления: «Пора повторить JOIN».
- AI-рекомендации на основе карты навыков.
- Автоматическая генерация дополнительных заданий для слабых мест.

### 13.4. Версия 1.3 — Адаптивность

- Персональный roadmap строится автоматически на основе карты навыков.
- AI Mentor может пропускать простые задания для сильных навыков.
- AI Mentor может добавлять дополнительные задания для слабых навыков.
- Диагностические тесты в начале курса (оценка текущего уровня).

### 13.5. Версия 2.0 — Продвинутая

- Полноценный SQL Sandbox с визуализацией данных (диаграммы, графики).
- Сравнение результатов двух запросов.
- Экспорт в CSV, Excel.
- Групповые отчёты (если несколько учеников).
- Интеграция с реальными производственными данными (импорт из 1С/ERP).
- Мобильная версия (чтение уроков, просмотр прогресса).
- Геймификация: достижения, рейтинг, серии.

### 13.6. Критерии готовности MVP

MVP можно считать готовым, когда:

1. Ученик может зарегистрироваться и войти.
2. Ученик видит dashboard с прогрессом и следующим уроком.
3. Ученик открывает урок, читает контент (12 разделов).
4. Ученик нажимает «Выполнить задание» — открывается SQL Sandbox.
5. Ученик пишет SQL-запрос, выполняет его, видит результат.
6. Ученик отправляет запрос на проверку — получает результат (пройдено/не пройдено).
7. AI Mentor даёт обратную связь по попытке.
8. Навыки ученика обновляются после успешной проверки.
9. Урок отмечается как пройденный.
10. Путь ученика от входа до feedback по заданию занимает не более 30 минут реального времени (при условии, что ученик знает SQL).
