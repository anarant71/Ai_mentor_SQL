# Урок 5. Первый JOIN

## 1. Зачем это нужно на производстве кресел

Руслан, производственные данные почти всегда лежат в нескольких таблицах. В BOM хранится `material_id`, а название материала лежит в `materials`. В плане производства хранится `chair_model_id`, а название модели - в `chair_models`.

`JOIN` нужен, чтобы соединять такие данные и получать понятный отчет.

На производстве кресел `JOIN` помогает:

- показать BOM вместе с названиями материалов;
- вывести план производства с названиями моделей кресел;
- связать остатки склада со справочником материалов;
- подготовить отчет, который можно читать без расшифровки UUID.

## 2. Теория

`JOIN` соединяет строки из двух таблиц по условию связи.

Базовый синтаксис:

```sql
SELECT
    table_1.column_1,
    table_2.column_2
FROM table_1
JOIN table_2
    ON table_2.id = table_1.table_2_id;
```

В этом уроке используем `JOIN`, который показывает только строки, где связь найдена в обеих таблицах.

Для читаемости часто используют алиасы:

```sql
FROM bom_lines AS bl
JOIN materials AS m
    ON m.id = bl.material_id
```

## 3. Пример SQL

Покажем строки BOM вместе с названиями материалов.

```sql
SELECT
    bl.bom_header_id,
    m.material_code,
    m.material_name,
    m.category,
    bl.quantity_per_unit,
    bl.scrap_percent,
    bl.line_type
FROM bom_lines AS bl
JOIN materials AS m
    ON m.id = bl.material_id;
```

## 4. Разбор результата

Запрос берет строки из `bom_lines` и для каждой строки находит материал в `materials`.

В результате экономист видит не просто `material_id`, а понятные данные:

- код материала;
- название материала;
- категорию;
- норму расхода на одно кресло;
- процент отходов;
- тип строки BOM.

Такой отчет уже можно использовать для проверки спецификации: видно, какие материалы входят в BOM и какие нормы расхода указаны.

## 5. Типичные ошибки ученика

1. Ученик забывает условие `ON`.
   Почему это ошибка: без правильного условия связи результат может стать неверным или PostgreSQL не выполнит запрос.

2. Ученик соединяет не те колонки.
   Почему это ошибка: `bom_lines.material_id` должен связываться с `materials.id`; если выбрать другую колонку, материалы будут сопоставлены неправильно.

3. Ученик не использует алиасы и путается в названиях.
   Почему это ошибка: в запросах с несколькими таблицами алиасы помогают экономисту быстро понять, откуда взята колонка.

4. Ученик выбирает только `material_id`.
   Почему это ошибка: UUID полезен базе, но человеку нужен код и название материала.

5. Ученик ожидает увидеть строки без материала.
   Почему это ошибка: обычный `JOIN` показывает только строки, где связь найдена в обеих таблицах. Для поиска отсутствующих связей позже нужен `LEFT JOIN`.

## 6. Практическое задание

### Условие

Выведи план производства вместе с кодом и названием модели кресла.

Используй таблицы:

- `production_plan`;
- `chair_models`.

Покажи колонки:

- `plan_date`;
- `model_code`;
- `model_name`;
- `planned_quantity`;
- `status`.

### Ожидаемый результат

В результате каждая строка должна показывать план выпуска, но вместо непонятного `chair_model_id` должны быть код и название модели кресла.

Такой отчет удобнее для экономиста, потому что его можно читать без ручной расшифровки идентификаторов.

### SQL-подсказка

Связь такая:

```sql
chair_models.id = production_plan.chair_model_id
```

Можно использовать алиасы:

```sql
FROM production_plan AS pp
JOIN chair_models AS cm
    ON cm.id = pp.chair_model_id
```

### Критерии проверки

- Использованы только таблицы `production_plan` и `chair_models`.
- Есть `JOIN`.
- В `ON` правильно связаны `cm.id` и `pp.chair_model_id`.
- Результат содержит дату плана, код модели, название модели, количество и статус.
- Запрос не использует запрещенные таблицы.

## 7. Проверочный вопрос

Почему экономисту удобнее видеть в отчете `model_code` и `model_name`, а не только `chair_model_id`?

## 8. Что ученик должен уметь после урока

После урока ученик должен уметь:

- соединять две таблицы через `JOIN`;
- писать условие связи через `ON`;
- использовать алиасы таблиц;
- превращать технические идентификаторы в понятный производственный отчет.
