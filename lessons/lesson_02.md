# Урок 2. Выбор колонок и синтаксис SQL

---

## Производственный контекст

Руслан, на прошлом уроке ты научился заглядывать в таблицу через SELECT *. Но звёздочка — это «все колонки разом». На производстве экономисту обычно нужны только конкретные данные.

Например, для отчёта по себестоимости достаточно названия материала и цены. Остальные колонки (id, дата создания) только мешают. В этом уроке ты научишься выбирать только нужные колонки.

---

## Теория

### Явный перечень колонок

Вместо SELECT * можно перечислить колонки через запятую:

```sql
SELECT
    model_code,
    model_name
FROM chair_models;
```

Теперь база вернёт **только две колонки**, а не все.

Правила:
- колонки перечисляются после SELECT через запятую
- порядок колонок — такой, как ты написал
- последняя колонка — без запятой в конце
- FROM — всегда после перечня колонок

### Порядок слов в запросе

В SQL важен порядок частей запроса. Пока мы знаем две:

```
SELECT  →  что показываем
FROM    →  откуда берём
```

Этот порядок **нельзя нарушать**. FROM всегда после перечня колонок.

### Почему SELECT * плох для отчётов

1. **Результат тяжело читать.** Если в таблице 15 колонок, а нужно 3 — остальные 12 занимают экран.
2. **Результат непредсказуем.** Если в таблицу добавят новую колонку, она появится в SELECT *.
3. **Код непонятен коллегам.** Читая запрос, они не видят, какие данные тебе нужны.

Правило: SELECT * — только для быстрой разведки. Для работы — явные колонки.

## Пример SQL

Посмотрим код и название модели:

```sql
SELECT
    model_code,
    model_name
FROM chair_models;
```

---

## Разбор результата

Запрос вернёт две колонки:

```
 model_code |          model_name
------------+-------------------------------
 CH-OP-100  | Операторское кресло Старт
 CH-OP-200  | Операторское кресло Комфорт
 CH-MG-300  | Кресло руководителя Престиж
```

Колонок ровно две — только то, что запросили.

---

## Типичные ошибки студентов

1. **Забывает запятую между колонками.** PostgreSQL думает, что это одно выражение.
2. **Ставит запятую после последней колонки.** Лишняя запятая перед FROM — ошибка.
3. **Пишет WHERE до FROM.** Нарушение порядка слов. FROM всегда после SELECT.
4. **Использует SELECT * в рабочем запросе.** Лишние колонки мешают читать результат.

## Практическое задание

🎯 **ЗАДАНИЕ**

Напиши запрос, который показывает material_code, material_name и current_price из таблицы materials.

Колонки должны идти именно в таком порядке: код, название, цена.

**Критерии проверки:**
- В SELECT перечислены три колонки: material_code, material_name, current_price
- Колонки в указанном порядке
- FROM materials

---

## Разбор решения

```sql
SELECT
    material_code,
    material_name,
    current_price
FROM materials;
```

Разберём:
- material_code, — первая колонка, с запятой
- material_name, — вторая колонка, с запятой
- current_price — третья колонка, запятой нет
- FROM materials — таблица
- ; — конец

---

## Почему это пригодится

Экономист, составляя отчёт по ценам материалов, выбирает только код, название и цену. Лишние колонки мешают — приходится скроллить вбок. Явный перечень колонок делает результат понятным и читаемым.
