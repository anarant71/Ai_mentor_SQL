# Урок 4. GROUP BY и агрегаты

## 1. Зачем это нужно на производстве кресел

Руслан, в работе экономиста часто нужно смотреть не отдельные строки, а итоги: сколько материалов в каждой категории, какая средняя цена, сколько кресел запланировано по моделям.

`GROUP BY` помогает собрать строки в группы и посчитать показатели по каждой группе.

На производстве кресел это нужно, чтобы:

- посчитать количество материалов по категориям;
- увидеть среднюю цену ткани, металла или упаковки;
- посчитать план выпуска по каждой модели;
- сравнить объемы работ между категориями кресел.

## 2. Теория

Агрегатные функции считают итог по строкам:

- `COUNT(*)` - количество строк;
- `SUM(column)` - сумма;
- `AVG(column)` - среднее значение;
- `MIN(column)` - минимум;
- `MAX(column)` - максимум.

`GROUP BY` указывает, по какой колонке собрать строки в группы.

```sql
SELECT
    category,
    COUNT(*) AS materials_count
FROM materials
GROUP BY category;
```

Если в `SELECT` есть обычная колонка и агрегат, обычная колонка обычно должна быть в `GROUP BY`.

## 3. Пример SQL

Посчитаем количество материалов и среднюю цену по категориям.

```sql
SELECT
    category,
    COUNT(*) AS materials_count,
    AVG(current_price) AS avg_price
FROM materials
WHERE status = 'active'
GROUP BY category;
```

## 4. Разбор результата

Запрос берет активные материалы и группирует их по `category`.

Для каждой категории PostgreSQL считает:

- `materials_count` - сколько материалов в категории;
- `avg_price` - среднюю текущую цену материалов.

Экономист может быстро увидеть, например, что в категории `component` много позиций, а средняя цена механизмов или металлических деталей выше, чем у упаковки.

## 5. Типичные ошибки ученика

1. Ученик выбирает обычную колонку, но не добавляет ее в `GROUP BY`.
   Почему это ошибка: PostgreSQL не понимает, какое значение этой колонки показать внутри группы.

2. Ученик группирует не по той колонке.
   Почему это ошибка: если сгруппировать материалы по `unit`, а нужен отчет по категориям, результат будет отвечать на другой вопрос.

3. Ученик забывает фильтр `status = 'active'`.
   Почему это ошибка: в отчет попадут архивные или заменяемые материалы, и средняя цена может стать неактуальной.

4. Ученик путает `COUNT(*)` и `SUM(current_price)`.
   Почему это ошибка: `COUNT(*)` считает строки, а `SUM` складывает значения. Это разные производственные показатели.

5. Ученик не задает понятный алиас.
   Почему это ошибка: без `AS materials_count` результат сложнее читать и использовать в отчете.

## 6. Практическое задание

### Условие

Посчитай плановое количество кресел по каждой модели из таблицы `production_plan`.

Покажи:

- `chair_model_id`;
- сумму `planned_quantity` с алиасом `total_planned_quantity`.

Используй только строки, у которых `status = 'approved'`.

### Ожидаемый результат

В результате должна быть одна строка на каждую модель кресла, которая есть в утвержденном плане.

Каждая строка показывает общий плановый выпуск по этой модели. Такой отчет помогает экономисту понять загрузку производства по моделям.

### SQL-подсказка

Используй:

```sql
SUM(planned_quantity) AS total_planned_quantity
```

И сгруппируй результат:

```sql
GROUP BY chair_model_id
```

### Критерии проверки

- Использована только таблица `production_plan`.
- Есть фильтр `WHERE status = 'approved'`.
- Использована агрегатная функция `SUM`.
- Есть `GROUP BY chair_model_id`.
- Сумма имеет алиас `total_planned_quantity`.
- Запрос не использует запрещенные таблицы.

## 7. Проверочный вопрос

Как экономист, чем отличается вопрос "сколько строк плана есть по модели" от вопроса "сколько кресел запланировано по модели"?

## 8. Что ученик должен уметь после урока

После урока ученик должен уметь:

- использовать `COUNT`, `SUM` и `AVG`;
- группировать строки через `GROUP BY`;
- понимать разницу между количеством строк и суммой производственного показателя;
- строить простой итоговый отчет по материалам или плану производства.
